## 代码入口及必须注意的行为

- `pathmnist_project.cli freeze` 调用 `experiment.freeze(data, runs)`：要求 `matrix.json` 与由显存试跑生成的完整 15 组一致、所有 `run.json` 已完成且非 smoke、manifest/source 标识一致；重新对 15 份 `best.pt` 测单线程、batch 1、50 次预热、500 次计时的 CPU 延迟，**覆盖原 `benchmark.json`**；以 A—D 三种子的平均验证 Macro-F1 和组内 CPU 中位延迟，按 0.005 容差选配置；再按验证 F1 选种子；生成 `frozen.json`，锁定每组 `best.pt`、`run.json`、`val_metrics.json`、`val_predictions.csv`、`benchmark.json` 的 SHA-256。
- 冻结函数在逐组复测中写 `benchmark.json`，直到最后才写 `frozen.json`，**不提供事务回滚**。因此启动前备份 15 份原基准及其哈希；若冻结在中途报错，应保留错误与部分新基准，不自行重复冻结或修改结果，先定位问题。`history.csv` 及旧验证核验文件没有被 `frozen.json` 锁定，需另记哈希以便报告复核。
- `pathmnist_project.cli evaluate` 先调用 `verify_data` 和 `validate_freeze`，随后对冻结矩阵全部 15 组逐次生成 `test_predictions.csv`、`test_metrics.json`、`test_provenance.json`；多数类基线只用训练标签选预测类。此函数**遇到已有测试文件仍会重写**，因此应保证第一次运行前没有任何测试结果文件，并只启动一个评价进程。中断后的重试只能在方案不变、记录中断原因及旧输出哈希后按同一固定协议统一重跑，绝不可依据已出的测试分数改配置。
- `pathmnist_project.cli summarize` 复算测试集的 Accuracy、Macro-F1、宏平均 AUC，检查逐图 ID/真实标签和冻结标识，然后制图和写摘要；它没有独立核验全部逐类指标、`predicted_label`、每行概率和 `test_provenance.checkpoint_sha256`。正式报告前需要单独的逐图、逐类复算。
- 已预注册的混淆类别对并列顺序与现有 `analysis.py` 一致：按混淆次数、`class_a`、`class_b` 均降序。切勿在冻结后修改 `pathmnist_project/*.py`，因为 `source_id` 会变化而使冻结验收失败。以后要更改报告图样式，应在独立的 `stage5/` 脚本中实现。

## 冻结、锁定检查、统一测试

确认上述条件后，在服务器仅启动一次冻结。不要使用 `scripts/run_gpu.py`，它会连带触发训练与最终测试。推荐将标准输出/错误和退出码保存在项目内；生产执行时用 `flock` 防止同一个项目重复启动。同一锁也用于后续评价。

```bash
cd /home/wenhao/pathmnist_course
mkdir -p stage5
flock -n stage5/finalization.lock sh -c '.venv/bin/python -m pathmnist_project.cli freeze --data data --runs runs/formal > stage5/freeze_stdout.json 2> stage5/freeze_stderr.log'
printf '%s\n' "$?" > stage5/freeze_exit_code.txt
```

只有退出码为 0 才继续。用 `.venv/bin/python` 调 `verify_data('data')` 与 `validate_freeze('data','runs/formal')`，复核 `freeze_id`、15 组 locks、每组 SHA-256、15 份基准的 `threads=1`、`batch_size=1`、`warmup=50`、`repeats=500`、`preprocessing_included=False`、环境一致，并用 `select_configuration` 对 `frozen.json.selection` 从**冻结后的验证指标与基准**独立重算。选中组必须属于 A—D；E 不参与演示选择。把选择依据、四组验证均值/组延迟、胜出种子、权重哈希和 `freeze_id` 写入 `stage5/`。冻结锁定后，任何正式包源码、数据或被锁文件变化都会令 `validate_freeze` 失败；若失败，不运行最终测试。

冻结成功并完成锁定核验后，固定 GPU 编号和读取进程数，执行一次 15 组统一评价；以下 `CUDA_VISIBLE_DEVICES=1` 指服务器原物理 GPU 1，进程内映射为 CUDA 0。若服务器当前 GPU 分配变更，应在启动前记录并选定一个可用编号。项目不依赖测试集来选择该编号。

```bash
cd /home/wenhao/pathmnist_course
flock -n stage5/finalization.lock sh -c 'CUDA_VISIBLE_DEVICES=1 .venv/bin/python -m pathmnist_project.cli evaluate --data data --runs runs/formal --device cuda --workers 4 > stage5/evaluate_stdout.log 2> stage5/evaluate_stderr.log'
printf '%s\n' "$?" > stage5/evaluate_exit_code.txt
```

评价成功后检查每组 `test_provenance.freeze_id == frozen.freeze_id`、`checkpoint_sha256 == SHA256(best.pt)`，全部 15 份测试预测行数等于官方有效测试集数量（预期 7,180）、列顺序为 `sample_id,true_label,predicted_label,p_0…p_8`、ID 与 `test_indices.npy` 对齐且唯一、真实标签与 `test_labels.npy` 对齐、概率有限且行和约为 1、预测标签等于概率最大列。独立复算 Accuracy、Macro-F1、宏平均 one-vs-rest AUC、九类 Precision/Recall/F1/AUC/灵敏度/特异性及 9×9 混淆矩阵，对照每份 `test_metrics.json`；多数类定义应为训练集标签计数最大类别。校验 15 组组内均恰好 3 个种子，计算均值与样本标准差。对所有测试输出做 SHA-256 快照，记录本次评价命令、时间与退出码。**只有这些检查通过**，才运行摘要入口：

```bash
.venv/bin/python -m pathmnist_project.cli summarize --data data --runs runs/formal --output artifacts
```

摘要图、最终报告与 PPT 应引用冻结 ID、逐图复核后的数值与训练配置，不因测试结果回头替换演示模型或添加新训练。外部中心测试只能支持图像块层面的泛化观察，不能当作患者级临床结论。

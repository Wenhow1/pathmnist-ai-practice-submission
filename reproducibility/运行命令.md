# 安全核查与复现说明

在**新的教师提交目录根**执行：

```sh
python3 -m unittest discover -s tests_submission -v
python3 checks/verify_submission.py --root .
```

只需要Python标准库。第一条运行本轮新编写的合成正负测试；第二条检查已有文件、SHA、ZIP结构、各模型保存混淆矩阵的Accuracy/F1以及选择规则。不导入PyTorch、不训练、不中途访问网络、不执行样本预测。缺少原模型和PNG会列为WARN，**基本材料通过不代表可运行演示通过**。

复制模型和固定PNG后，可进一步运行：

```sh
python3 checks/verify_submission.py --root . --require-demo-assets
```

这是更严格的资产完整性门槛，仍不是模型行为验收。正式部署验收必须另行运行便携应用，记录平台、命令、退出码、图像输出及异常行为。

原训练包在 `technical/source_snapshot`，原版本环境清单位于该目录。当前CI不安装或运行这些重型依赖。原CLI保留是为了审查与独立环境重现，默认不得运行 `evaluate`、`freeze` 或完整GPU训练脚本，更不能指向原已冻结实验目录。

GitHub Actions配置位于 `.github/workflows/quality-check.yml`；它只运行前两条提交检查。云端运行状态为空或pending时，不展示绿色“已通过”徽章。通过后也只代表此范围的文件与算术检查，不代表模型训练或临床验证。

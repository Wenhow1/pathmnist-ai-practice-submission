# AI使用日志与交互案例

本附件以保存的阶段AI日志、原始提示、源码审阅和验收记录为依据，说明人怎样把任务交给AI，怎样处理其输出，以及哪些内容未被采纳。它不是完整聊天逐字导出，也不补画不存在的聊天截图。原件均保留在evidence/source；文中S编号见reference/来源编号与阅读索引.md。

## 1 记录分类与使用原则

| 标记 | 含义 | 使用方式 |
|---|---|---|
| 原话节选 | 能在保存的日志／当前对话中定位的文字 | 使用引号或引用块，注明来源，不伪装成整段完整会话 |
| 日志摘要 | 根据阶段记录整理的任务与响应 | 不加“原始提示词”标签，不推测未记录上下文 |
| 源码事实 | 从指定代码或配置直接可见 | 说明文件和作用，不等于新运行 |
| 历史实测 | 原命令、日志、指标或设备验收 | 保留时间和环境范围，不称本轮复跑 |
| 本轮整理／新增检查 | 当前文稿、目录与静态校验工具 | 与历史模型成果分开；云端执行需真实记录 |

## 实际工具角色

ChatGPT参与对话、方案讨论、交接、材料解释和提交组织；Codex承担大部分仓库、终端、训练与验证实现；DeepSeek网页仅有第六阶段风险审查及草稿记录。项目未使用Claude Code。不同AI的相互审查不是自动的独立实验认证。[S02、S08、S13–S14]

交接包的写作会话没有GitHub写入接口。2026年10月19日由现有Codex会话接手发布；没有另建任务，也不把新发布动作倒记为原训练期操作。

# 2 从选题到交付的阶段日志

| 阶段 | 输入任务与约束（摘要） | AI产物及执行 | 核查／取舍 |
|---|---|---|---|
| 选题 | 医学图像方向；子集由助手推荐 | PathMNIST任务、数据与对照建议 | 未记录多数据集性能海选 |
| 数据环境 | 只在本人服务器目录；不在本机下载完整数据 | 环境、数据下载、manifest、分布图 | MD5与数组检查；患者ID限制保留 |

| 冻结测试 | 锁定后评价；不覆写既有证据 | D_seed2026选择、15条统一测试 | E更高也不倒改本轮选择 |
| 量化 | 冻结后仅train校准、val验收 | DeepSeek草稿、Codex PTQ与图表 | 原两版失败记录保留 |
| 第七阶段 | 不重训、不重开测试、独立演示与补证据 | 原CSV复制核验、CLI/UI、有限PTQ | 候选通过精度门槛仍更慢，默认FP32 |
| 当前提交 | AI实践为主，原仓库不动，新仓库独立 | 新主报告、附件、同步PPT、提交目录 | 云端发布与CI已实测；教师访问仍待验收，不回写历史 |

以上是工作流摘要，不把所有代码生成和执行归为同一次提示。主要来源：S02、S05–S10、S13–S14、S20。

## 阶段衔接

阶段总结不是单纯“完成百分比”，而应说明产物路径、核验结果、未决问题与下一步是否得到批准。用户多次提出范围和不覆盖约束，Codex再依据当前源码与产物落实；由此把聊天中的意图保存在项目文件中。

# 3 案例一：把方向描述变成明确任务

## 原话与摘要分开

来源：docs/AI使用日志.md，第二阶段条目。[S02]

“选择医学图像方向，将具体子集交由助手推荐”属于同一日志中的人工决策摘要；它不是本附件重新取得的一段完整原始聊天。此处不用虚构的聊天气泡展示。

## AI如何拆解

任务从领域方向细化为PathMNIST数据、九类标签、官方划分、模型与尺寸比较、D/E消融、种子、训练设置、评价指标和冻结规则。相应产物是方法协议、matrix、manifest、代码及阶段文档。配置形成经历多轮推进，不应声称“一句提示自动生成最终全部设计”。[S02–S06]

## 原始约束的工程作用

| 约束 | 落到文件或执行上的作用 |
|---|---|
| 只使用本人项目目录 | 环境、下载缓存和运行输出限定在约定项目范围 |
| 不把完整数据下载到本机 | 大数据与权重留在服务器，轻量证据另行复制 |
| 每阶段保留记录 | 保存命令、日志、配置、来源标识与图表 |
| 先检查再扩大 | 小样本测试不能省略，也不能将其分数并入正式实验 |

后来当用户允许数据在服务器下载或调整运行范围时，记录注明了授权变化，没有把最初限制当成永远不变，也没有无依据推断新的授权。

## 可以从这个案例学到什么

有效交互不仅包含目标，还应给出上下文、边界和验收方式。字段如何固定、图像尺寸如何选择仍需要在后续实现中检查；任务文档不是正确性的替代品。

# 4 案例二：ChatGPT建议由Codex回到源码核对

**日期与性质：** 2026-09-23；方案评审，不是新增实验启动。用户把ChatGPT对话中的PATHMNIST_EXPERIMENT_V2.md与CODEX_START_HERE.md交给Codex，并要求判断建议是否适用。原建议正文在本附件中不重建，仅引用已归档审阅表。[S08]

| 对话中的建议 | 源码／协议核对 | 采纳状态与证据 |
|---|---|---|
| 需要补自动早停 | 已有验证Macro-F1早停 | 否决“缺失”判断，不重复实现 |
| 需要完整断点恢复 | best.pt缺优化器、调度器、随机状态 | 采纳，但在独立resume_v2目录实现 |
| 40轮直接续到200轮 | T_max变更影响学习率轨迹 | 不当原训练延续；未默认启动 |
| 更多轨迹与新的增强消融 | 建议参照不等于原E组 | 先完成原协议，不照搬建议预算 |
| 高分值得核查 | 数据与代码审计具有实际价值 | 采纳只读审计，保留患者ID限制 |

实际恢复原型有本地合成检查及历史GPU短轨迹验收；连续4轮与2+2恢复的24项状态比较一致。它不构成第四个种子或新的正式模型结果。[S09]

**对协作的影响。** ChatGPT可以帮助提出结构化方案，但执行代理必须掌握当前代码状态；Codex的核对也要留下依据。这个案例避免了把另一对话的假设直接转成大量新增训练。

**未确认个人归属。** 日志记有用户提出审阅任务、Codex完成审阅与实现；没有署名证据的逐行人工审核，不归给具体组员。

# 5 案例三：DeepSeek审查和草稿的选择性采用

**日期：** 2026-09-28。实际界面为DeepSeek网页。输入为公开方法概述，不上传完整源码、原图、逐图预测、服务器地址或凭据。[S13]

## 原始提示节选

> 请给出：1）按严重性排序的最多6个实施或解释风险及相应验收办法；2）一段不超过50行的Python函数，接收相同顺序的y_true、FP32九类概率数组和INT8九类概率数组，验证形状/有限值/概率和……请只依据上述公开方法信息回答，不假设你已运行该项目。

省略处仅为缩短显示，完整原话见原记录。函数接口、数据角色与不使用测试集调参等条件也在原提示中说明。

## 反馈与处理

DeepSeek提出校准和验收集分工、S8S8数值风险、计时可比性、概率接口、校准采样偏差和逐类退化等风险。指标草稿存在输入检查不完整：0—8标签、非负概率、非空样本和固定九类labels未完整约束。该函数未进入正式指标管线，沿用已有classification_metrics。[S13]

第二次提示请求从comparison.json生成对比图，不访问网络和原图。草稿经过协议、非法数值、P95、文字位置及字体修订后，先用合成JSON验收。合成数据图不用于正式结果，正式图来源为真实量化汇总。

**结论。** AI草稿可以被拒绝；两个不同工具参与，不等于自动获得两份实测证据。“人工修订”没有具体署名的部分保持待确认，不写成某位组员完全独立实现。

# 6 案例四：复核脚本失败，只修复核验链条

第五阶段模型已经产生正式测试预测，独立复核程序首次读取混淆矩阵时，将JSON列表误当对象，导致程序停止。修复的是读取类型，再重新运行复核脚本；正式测试预测没有重跑或修改。[S10]

| 需要区分 | 此次实际对象 |
|---|---|
| 原始实验产物 | 冻结模型已生成的测试预测与指标 |
| 出错程序 | 读取和比较这些产物的独立复核脚本 |
| 修复范围 | JSON类型处理 |
| 重跑范围 | 复核脚本，而非模型训练或测试预测 |
| 最终证据 | 修复后的核查记录与原结果来源仍一致 |

如果因为核验程序报错就重新生成测试预测，既不能直接解决类型问题，还可能覆盖原证据。保留失败和控制修复范围，是Harness在真实工程中的具体作用，而不是要求系统永远不出错。

## 关联案例：演示路径与文件保护

第七阶段把依赖原服务器路径的演示整理为独立CLI/UI，默认FP32，检查模型SHA、标签、布局与预处理，限制路径越界，输出使用拒绝覆盖的方式。已有搬迁目录、断网与异常输入记录，但不等于当前新教师目录已经包含模型、样例或完成运行。[S17–S18、S21]

# 7 案例五：量化诊断、重试与证据边界

**任务摘要。** 第七阶段要求限时、只用train/val诊断，若有明确线索才有限追加PTQ，不打开官方测试，不自动QAT。[S14–S15]

## 问题与修复顺序

| 问题 | 处理 | 没有做的事 |
|---|---|---|
| reader缺迭代接口 | 修订数据读取，保留失败退出码 | 不删除失败记录 |
| uint8调试助手计算回绕 | 提升类型并用反量化对照复核 | 不认定其为实际ONNX推理失败根因 |
| 原量化分数严重下降 | 根据训练样例线索登记五Conv浮点候选 | 不用测试集挑量化参数 |
| 初次候选验收基线路径错误 | 对照候选SHA，修正路径后再核验 | 不将启动成功当完整验收成功 |
| 候选精度恢复、速度仍慢 | 保存候选与各自基线，默认FP32 | 不把压缩率改称加速率 |

历史记录区分18张独立诊断样例、576张训练校准样例与10,004张验证图像；含重试的验证处理张次不等于更多独立样本。完整验证F1为0.9956677882，现存记录为工程验收，未形成新外部测试。[S15–S16]

## 为什么保留失败也有报告价值

本案例允许看到输入接口、辅助工具、数据路径和性能目标四类问题；它们需要不同检查，不能统一称为“模型不够好”。本轮重新组织材料没有重新执行上述命令，历史验收和当前文稿检查分开。
